# 回声密令：完整游戏流程

本文以 5 名玩家为例，描述当前原型的真实流程、状态变化和比赛现场的演示方式。

## 1. 游戏目标

5 名玩家组成一支“回声小队”，轮流复述系统给出的中文密令。每次复述都会生成一个匹配度分数，分数累加到当前玩家，同时汇总到团队进度。完成 5 轮后结束本局，个人总分最高者可以作为 MVP，团队进度用于展示整体完成度。

当前原型是合作接力模式，不设置狼人、隐藏身份或跑团叙事。每一轮使用一条密令，5 名玩家各完成一次后进入下一轮，所以一局完整对局共有 25 次回合。

## 2. 五人角色

示例玩家如下：

| 顺序 | 玩家 | 初始身份 | 第一轮回合 |
| --- | --- | --- | --- |
| 1 | 小满 | 房主 | 第一个复述 |
| 2 | 阿岛 | 普通玩家 | 第二个复述 |
| 3 | 北北 | 普通玩家 | 第三个复述 |
| 4 | 你 | 普通玩家 | 第四个复述 |
| 5 | 禾木 | 普通玩家 | 第五个复述 |

房主只负责开始游戏，不获得额外分数或特殊能力。回合顺序按照加入房间的顺序固定，后续每一轮从小满重新开始。

## 3. 开局准备

### 3.1 启动服务

项目根目录打开两个终端：

```bash
go run ./backend
```

```bash
cd frontend
npm run dev
```

访问 <http://localhost:5173>。比赛现场建议使用 Chrome 或 Edge，并确认浏览器允许麦克风权限。

### 3.2 创建房间

1. 小满输入昵称，点击“创建房间”。
2. Go 服务生成 4 位房间码，例如 `MGMP`。
3. 小满成为房主，页面进入等待大厅。
4. 房间初始状态为 `lobby`，回合数显示为 0/5。

### 3.3 加入房间

1. 阿岛、北北、你、禾木分别在自己的浏览器打开页面。
2. 输入昵称和房间码 `MGMP`，点击“加入”。
3. 右侧玩家列表实时出现 5 名玩家。
4. 每位玩家点击“我准备好了”。
5. 房主可以看到所有人的准备状态。

当前实现允许房主在至少 2 名玩家加入后开始，不强制检查所有人都已准备；比赛演示建议等 5 人全部显示“已准备”再开始。

## 4. 开始游戏

1. 小满点击“开始游戏”。
2. 后端确认请求来自房主，并确认房间至少有 2 名玩家。
3. 房间状态从 `lobby` 变为 `playing`。
4. 回合数变为 1/5。
5. 当前玩家设置为小满。
6. 第一条密令为：`雨后的电车穿过橘色隧道`。
7. 每个浏览器每秒刷新一次房间状态，所以所有玩家会看到相同的当前回合和玩家列表。

## 5. 一轮的具体过程

以第 1 轮为例，回合顺序如下：

### 5.1 小满回合

1. 小满看到状态“你的回合”。
2. 点击“重播密令”可以用浏览器语音合成听到密令。
3. 小满按住“按住开始说”。
4. Chrome/Edge 会启动中文语音识别；不支持该 API 时使用演示回声。
5. 小满松开按钮，前端提交 `player_id` 和识别出的 `transcript`。
6. 后端计算匹配度，例如 92 分，并将小满个人分数增加 92。
7. 状态切换到阿岛，所有客户端显示“等待队友”或“阿岛的回合”。

### 5.2 阿岛、北北、你、禾木回合

其他 4 名玩家重复同样的步骤。每位玩家完成后：

- 当前玩家分数增加本次匹配度；
- 右侧排行榜显示最新分数；
- “上一条回声”区域显示识别文本和匹配度；
- 回合顺序移动到下一位玩家。

禾木提交后，`CurrentIndex` 回到 0，回合数从 1 增加到 2。

## 6. 五轮完整顺序

| 轮次 | 密令 | 回合顺序 | 结束条件 |
| --- | --- | --- | --- |
| 第 1 轮 | 雨后的电车穿过橘色隧道 | 小满 → 阿岛 → 北北 → 你 → 禾木 | 禾木提交 |
| 第 2 轮 | 月亮把影子藏进玻璃杯 | 小满 → 阿岛 → 北北 → 你 → 禾木 | 禾木提交 |
| 第 3 轮 | 三只蓝色纸船顺流而下 | 小满 → 阿岛 → 北北 → 你 → 禾木 | 禾木提交 |
| 第 4 轮 | 晚风带来一颗会唱歌的种子 | 小满 → 阿岛 → 北北 → 你 → 禾木 | 禾木提交 |
| 第 5 轮 | 森林尽头亮起一盏紫色信号灯 | 小满 → 阿岛 → 北北 → 你 → 禾木 | 禾木提交后结束 |

第 5 轮最后一名玩家提交后，房间状态变为 `finished`。当前界面会保留最后一次结果和排行榜，后续可以增加“再来一局”按钮。

## 7. 计分规则

后端接口接收 `transcript` 后进行字符级匹配：

1. 去除标点和空格；
2. 统计识别文本中与目标密令重复的不同字符；
3. `匹配字符数 / 目标字符数 × 100` 得到分数；
4. 最低分为 45，最高分为 99；
5. 没有识别文本时使用 78 分的演示回退值。

示例：目标密令为“雨后的电车穿过橘色隧道”，识别文本为“雨后的电车穿过橘色隧道”，本次得分接近 99；如果只说出其中一部分，分数会下降，但不会低于 45。

## 8. 聊天和同步

右侧“现场短讯”用于队友交流，例如“准备好了”“听清了吗”。发送消息后，后端保存最近 30 条。前端每秒请求一次房间状态，因此玩家列表、分数、当前回合和聊天会在约 1 秒内同步。

## 9. 异常情况

- **Go 服务未启动**：点击按钮会显示“无法连接 Go 服务，请先在项目根目录运行：`go run ./backend`”。
- **房间不存在**：加入时显示“房间不存在”，需要确认房间码或重新创建。
- **房间已满**：最多 8 人，第 9 人加入会被拒绝。
- **不是当前回合**：后端拒绝重复提交，返回“还没轮到你”。
- **浏览器不支持语音识别**：可以继续试玩，系统会使用演示回声；接入灵矽 SDK 后可替换该适配层。
- **刷新页面**：当前原型把玩家身份保存在浏览器 `localStorage`，但房间数据只保存在 Go 进程内存中；Go 服务重启后房间会消失。

## 10. 比赛现场推荐演示脚本

1. 提前启动 Go 和 Vue，打开 5 个浏览器窗口。
2. 用“小满”创建房间，把房间码投屏或发给其他 4 位玩家。
3. 5 人加入并全部点击准备。
4. 房主点击开始，先用“重播密令”演示听取动作。
5. 5 人依次完成第一轮，展示当前玩家高亮和分数变化。
6. 继续完成第 2 轮，展示密令更换和团队进度。
7. 可跳过剩余轮次进行功能讲解，或完整跑完 25 次回合展示结束状态。
8. 最后说明灵矽 SDK 尚未接入，当前语音适配层已预留替换位置。
